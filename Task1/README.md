Задание 1. Планирование: анализ, идентификация проблем и поиск решений

1. Анализируйте схему и описание системы

- Отсутствует наблюдаемость - нет мониторинга, логирования и трейсинга. Невозможно понятия, где произошел инцидент.
- Отстутствует механизм кэширования - все читается из бд, включая часто запрашиваемый список заказов
- Отсутствие отказоустойчивости - один экземпляр сервисов и БД.
- Низкая производительность списков - медленная загрузка списка заказов с учетом пагинации.
- Возможная потеря сообщений через RabbitMQ
- Сложности с масштабирования при росте нагрузки - с открытием API и выходом на новые рынки RPS вырос, но инфраструктура не изменилась
- Долгий расчет стоимости заказа - расчет синхронный и блокирующий.


2. Инициативы:
    * Внедрить мониторинг (Prometheus/Grafana) - высокий приоритет.
    * Внедрить логирование (ELK) - высокий приоритет.
    * Внедрить трейсинг (OpenTelemetry + Jaeger) - высокий приоритет.
    * Провести оптимизацию загрузки списков заказов в MES, внедрить кэширование (серверное, паттерн Write-through + Redis) - нормальный/высокий приоритет.
    * Расчет стоимости заказа должен быть асинхронным с уведомлением по очереди - нормальный приоритет.
    * Обеспечить отказоустойчивость RabbitMQ Dead-Letter exchange, Retry, мониторинг очередей - нормальный/низкий приоритет.
    * Обеспечить горизонтальное масштабирование сервисов и репликацию БД - нормальный приоритет.
    * Внедрить Circuit Breaker(паттерн) для защиты от каскадных сбоев при вызове внешних API - низкий приоритет.
    * Внедрить CI/CD с авто-тестами и откатом для ускорения релизов - низкий приоритет.

3. Реализация инициативы в порядке приоритета и стратегия
Целевая архитектура через 6 месяцев:
    * Мониторинг взаимодействует с ключевыми сервисами, логами и позволяет выполнять трейсинг.
    * Время отклика MES UI уменьшино за счет кеширования.
    * Асинхронный расчет стоимости и не приводит к блокировкам.
    * Система справляется с пиковым нагрузкам и отказам внешних сервисов.
    * Все заказы обрабатываются, все статусы фиксируются через RabbitMQ.

Инициативы (только 3) на ближайшие 6 месяцев:
    * Внедрение мониторинга системы для разбора инцидентов, оценки эффективности других изменений, управляемостью системы во времени.
    * Кеширование списков заказов MES (улучшение UX).
    * Асинхронные операции по расчетам стоимости (учучшение стабильности и эффективности API).
