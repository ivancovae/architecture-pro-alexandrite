Задание 3. Трейсинг

1. Места где заказ может зависнуть 
- Взаимодействие Shop API с MES API, в частности загрузка 3D-модели и расчет стоимости.
- Взаимодействие MES API с RabbitMQ, в частности публикация события о завершении расчета.
- Взаимодействие RabbitMQ с CRM API, в частности прием и подтверждение заказа.
- Взаимодействие MES API с MES UI, в частности назначение заказа оператору.
- Взаимодействие MES API с MES DB, в частности запись заказа и его статуса.

2. Данные которые должны попадать в трейсинг
- trace_id - ID заказа-запроса.
- URL запроса.
- span_id - этап обработки (расчет, публикация, прием и т.д.).
- order_id - ID заказа.
- имя очереди для сообщений.
- service_name - имя сервиса.
- Время входа и выхода из этапа обработки.
- HTTP метод.
- routing key.
- код ответа или флаг ошибки.

3. Мотивация
Отстутствие трейсинга приведет к:
- Трудностям по определению дошeл ли статус до CRM и был ли зарегистрирован.
- Сложностям понимания, где потерялся заказ.
- Сложностям диагностирования долгих расчeт стоимости.

Улучшаемые Метрики:
- Улучшение взаимодействия по API с партнерами (SLA по заказу < 1 часа).
- Снижение нагрузки на поддержку при инцидентах, меньше ручных разборов и привлечения специалистов. 
- Время реакции на жалобы клиентов (с суток до ~10 минут).
- MTTR (Mean Time To Resolve) инцидентов, а именно среднее время восстановления после сбоя работы системы.
- Процент зависших заказов, в идеале прийти к 0% зависших заказов.

4. Предлагаемое решение
- Добавление OpenTelemetry (SDK + Collector).
- Внедрение и использование Jaeger (UI + Storage).
- [Схема](./jewerly_c4_model_new.drawio)

Инструменты:
- Внедрение в Shop API OpenTelemetry SDK.
- Внедрение в CRM API OpenTelemetry SDK.
- Внедрение в MES API OpenTelemetry SDK.
- Через заголовки сообщений, при HTTP-вызовах и в RabbitMQ, передаются заголовки traceparent.
- Данные отправляются в Jaeger через OpenTelemetry Collector.

5. Компромиссы
- Технология RabbitMQ не поддерживает контекст автоматически, потребуется вручную копировать trace_id в заголовки сообщений, возможно будет затратно.
- OpenTelemetry потребует интеграции в MES (C#) вручную, нет готового auto-instrumentation, как например, в Java, возможно будет затратно.
- Трейсинг распространяется на файлы в хранилище S3, но это не приоритетно, и не мешает отслеживанию статусов заказа.

6. Безопасность
- Jaeger UI доступен только внутри защищенного контура и защищен, например, через SSO.
- Конфиденцинальные и внутренние данные (логины, email, личные даннык и тд) не включаются в трейсы.
- Доступ имеют DevOps, Бэкенд-разработчики, служба поддержка.
