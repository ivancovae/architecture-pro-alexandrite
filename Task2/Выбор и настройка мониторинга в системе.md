Задание 2. Мониторинг

1. Мотивация

Мониторинг обеспечит возможность анализа системы в момент исполнения и позволит быстрее реагировать на инциденты в проде (например, потеря заказов, замедление MES, наблюдение за системой "под нагрузкой")

Для компании "Александрит" мониторинг даст:
- Прозрачное наблюдение за работой сервисов.
- Уменьшение времени определения инцидента и реагирования на сбои.
- Сокращение времени на поиск причин проблем.
- Повышение репутации перед клиентами и партерами.

Ценности для бизнеса:
* Поможет количественно оценить качество сервисов.
* Определить слабые места системы.
* Определение причин проблем у пользователей, клиентов, заказчиков.
* Обеспечит сбор данных для анализа и развития бизнеса (экономия денег, так как можно адаптироваться под нагрузки "по факту").


2. Выбор подхода к мониторингу

* API сервисы (Shop API, CRM API, MES API) - подход RED, позволит оценить сервисы, выявлять проблемы "по факту".
* Инфраструктура (метрики CPU, метрики Памяти, БД) - подход USE, позволит определять нагрузку на "железо", полезен будет для MES (много ресурсов).
* Оценка системы (общие показатели выполнения) - подход "Четыре золотых сигнала", полезно для оценки работы системы в целом.

3. План действий
- Развернуть, в облаке, Prometheus и Grafana.
- Интегрировать функционала для выдачи метрик в Shop API, CRM API, MES API.
- Настроить выдачу метрик в RabbitMQ (rabbitmq_prometheus plugin).
- Конфигурировать "Дашборды" по каждому сервису и общую панель "состояния заказов".

Установить "Алерты":
- RPS>90% от пикового показателя.
- Number of HTTP 5xx>1% от общего трафика.

Показатели насыщенности (Saturation)
- При 80% от макс подключений к БД инициировать "Алерт", кроме того выполнять авто-масштабирование.
- MES API CPU>70% инициировать "Алерт", кроме того проводить ручной анализ.
- MES API memory>80% инициировать "Алерт", кроме того проводить ручной анализ.
- При >100 сообщений в очередь RabbitMQ инициировать "Алерт", кроме того проводить проверку потребителей.

При превышении порогов
- мгновенное уведомление на почту.
- автоматический саппорт в Таск-менеджере.
- при повторном срабатывании вызов дежурного инженера.
